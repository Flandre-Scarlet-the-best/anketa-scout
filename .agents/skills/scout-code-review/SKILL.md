# Независимое ревью

## Объект и независимость

Исходная задача и действующие контракты важнее самооценки автора в PR. Установить owner/repo, base/head и merge-base; для PR проверить истинные SHA и возможный dirty worktree. Не делать вывод по одному diff без окружающих потребителей и тестов. Самопроверку не называть «независимой», если отдельный рецензент не участвовал.

Ревью **только для чтения**: не изменять проверяемый проект, ветки, комментарии и PR и не запускать CodeRabbit. При отдельной просьбе исправить или опубликовать — перейти к [scout-git-workflow](../scout-git-workflow/SKILL.md).

## Вспомогательные инструменты

Без отдельного разрешения можно создавать и запускать одноразовые анализаторы, тестовые данные и отчёты, если это необходимо для доказательства. **Все созданные ревьюером вспомогательные файлы** хранить исключительно в изолированном каталоге системного temp **вне** репозитория, его worktrees и `.codex/local/`. Не изменять исполняемую реализацию под видом проверки. Существующие команды Cargo могут использовать штатную `target/` для сборки, не меняя исходники.

Отдельно проверять фактический путь temp, включая переменные окружения, и исключить попадание файлов в Git. После проверки удалять только свои временные результаты. Если безопасный temp недоступен, работать без записи и указать ограничение. Глобальные настройки и состояние чужой системы не менять.

## Порядок и результат

1. Зафиксировать постановку, ограничения, базу, проверяемый SHA и diff, включая новые файлы.
2. Прочитать применимых [владельцев](../../../.codex/context/INDEX.md) и пройти [критерии](references/review-criteria.md) по всем релевантным категориям.
3. Проследить реальный путь данных от входов через потребителей и побочные эффекты, проверить негативные сценарии, переносимость и регрессии.
4. Выполнить доступные проверки из [VERIFICATION.md](../../../.codex/context/VERIFICATION.md); отделять пройденное, не запущенное, проваленное и существовавшие ошибки.
5. Классифицировать замечания строго по [finding-policy.md](references/finding-policy.md); описать место, воспроизводимое условие, нарушенный контракт и последствие. Не считать вкус причиной изменения.
6. Выдать один из `CLEAN` / `COMMENT` / `REQUEST_CHANGES` / `INCOMPLETE` и границы доказательства. Без критического покрытия нельзя объявлять CLEAN. Порядок и формат — [review-workflow.md](references/review-workflow.md).

Внешние отзывы — гипотезы, не источник истины. После изменения HEAD или dirty diff ревью устаревает.
