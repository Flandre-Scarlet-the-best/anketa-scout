# Независимое ревью

Установить требования задачи, repository/base/head, merge-base и незакоммиченный
diff. Для PR сверить реальную ветку и SHA с checkout. Прочитать владельцев из
[индекса](../../../.codex/context/INDEX.md) по затронутым областям.

Изучить полный значимый diff и окружающий контекст: производители и потребители
данных, вызовы, ошибки, тесты, зависимости и документацию. Проверить соответствие
требованиям, переносимость, границы доверия, владение ресурсами и отсутствие
необоснованных специальных случаев. У конфигурации проверить реальную семантику,
а не только корректность синтаксиса. Проверки выбирать по
[VERIFICATION.md](../../../.codex/context/VERIFICATION.md).

Замечание требует места (файл/строка), нарушенного контракта, воспроизводимого
условия и последствия. Указать серьёзность и направление исправления; повторные
симптомы одной причины объединить. Недостаток данных обозначать как неопределённость,
не выдумывать дефекты и не предлагать косметические переделки ради вкуса.
Отделять новые регрессии от старых проблем. Внешний reviewer — источник гипотез,
а не авторитет, освобождающий от проверки.

Не менять файлы, не публиковать комментарии и не запускать CodeRabbit в рамках
обычного ревью. Если автору нужен независимый проход, использовать отдельно
порученного рецензента/агента; при отсутствии такого прохода честно назвать результат
самопроверкой. Делегирование не подразумевается одной лишь загрузкой skill.

Итог: замечания по серьёзности, проверенная ревизия и dirty diff, соответствие
задаче, фактические проверки и ограничения. Отсутствие замечаний не является
гарантией отсутствия дефектов. При изменении HEAD или рабочего diff выводы требуют
пересмотра. Исправление и публикация — отдельное поручение по
[scout-git-workflow](../scout-git-workflow/SKILL.md).
