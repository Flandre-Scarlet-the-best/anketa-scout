# Порядок независимого ревью

## 1. Установить объект

Записать owner/repo, base/head и их точные SHA, dirty changes, исходные требования. Не выбирать PR по заголовку; подтвердить ветку через GitHub. При отсутствии постановки не придумывать её.

## 2. Проследить поведение

Прочитать diff и окружающие производители/потребители, тесты, архитектурные зависимости. Для каждой области из [review-criteria.md](review-criteria.md) установить наблюдаемый сценарий и границу возможного сбоя. При анализе источника не скачивать и не публиковать персональные данные ради одного ревью.

## 3. Проверить гипотезы

При необходимости создать одноразовый помощник в системном temp, выполнить штатные проверки из `VERIFICATION.md`, минимальное воспроизведение или статический разбор. Не модифицировать проверяемый код и не открывать PR. Различать непроверенное, проваленное и успешное.

## 4. Вывести результат

Сначала найденные проблемы, отсортированные Critical → Major → Minor → Trivial. Каждая по [finding-policy.md](finding-policy.md), с точным воспроизведением и последствиями. Затем состояние требований, проверенный SHA, фактически запущенные проверки и ограничения.

Статусы `CLEAN`, `COMMENT`, `REQUEST_CHANGES`, `INCOMPLETE` взаимоисключающие. Если существенная часть недоступна — `INCOMPLETE` даже при нуле находок; перечислить, что необходимо для завершения. Непроверенные гипотезы — отдельно.

## 5. Независимость

Не запускать CodeRabbit, не публиковать комментарии, не делать commit/push и не менять файлы. Если поручено исправить/опубликовать — отдельный переход к `scout-git-workflow`. Любое изменение проверяемого HEAD требует новой оценки охвата.
