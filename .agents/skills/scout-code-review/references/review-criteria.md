# Критерии независимого ревью

Применять только категории, затронутые изменениями, но каждый исключённый значимый риск объяснить.

## Обязательное для любого изменения

- **Контракт задачи:** сделано именно порученное, сохранены несовместимые и отрицательные требования; не подменена область изменения.
- **Окружение:** прочитан полный существенный diff, новые файлы, вызывающие/вызываемые функции, потребители форматов и сообщений, tests, конфигурация и документация.
- **Регрессии:** проверь прежние случаи, пустые значения, некорректный ввод, частичный успех, отмену, сбой записи и повторный запуск.
- **Переносимость:** Windows/Linux/macOS, пути, кодировки, доступ к файлам, терминал, локаль, границы MSRV; не выводить переносимость только из одной платформы.
- **Безопасность:** контролируемые и недоверенные данные не превращаются в команды, URL, файловые пути, ANSI/OSC/bidi, поддельные рамки; отсутствие утечки контактов в логи/отчёты.
- **Ресурсы:** лимиты размера/времени/памяти, завершение потоков, таймауты, отсутствие бесконечных повторов.
- **Доказательства:** тест действительно исполняет изменённый путь; заглушка не выдаётся за внешний сервис. Нет тайной зависимости от локального снимка или приватных ключей.

## Rust/CLI и источники

- Разделение domain/application/source/transport, без предметной логики в HTTP или форматировании.
- Ошибки typed и отличимы от пустого результата; отмена не маскируется успешной выдачей.
- Источник: идентичность треда, схема JSON/HTML, количество постов, уникальность, происхождение и OP; безопасность редиректов и вложений.
- Контакты: принадлежность автору, цитаты/образцы, канонизация и дедупликация, неизвестная платформа, ложноположительные результаты, сохранение исходного текста.
- Таблицы: узкие ширины, Unicode grapheme, многострочные ячейки, отсутствие управляющих последовательностей из источника, BrokenPipe/flush и потоки stderr/stdout.
- Cargo/toolchain: закрепление MSRV, feature combinations, lockfile, уязвимые версии, опубликованность внешних действий.

## GitHub/агентские контракты

- PR-процессы не обходят Draft/Ready/merge или проверку удалённого SHA.
- Не дублируются владельцы, относительные Markdown-ссылки и входы Claude ведут к каноническому файлу.
- Настройки GitHub Actions не запускают недоверенный PR-код с привилегиями; не допускаются секреты, неподтверждённые статусы и самопроверяющийся валидатор при доверенной проверке.
- Изменения Renovate/CodeRabbit проверены по официальной схеме и фактической семантике, а не только по «валидный JSON».

`VERIFICATION.md` выбирает конкретные проверки, этот документ — перечень вопросов ревью, а не второй реестр команд.
