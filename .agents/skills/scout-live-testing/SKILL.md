# Живая приёмка Anketa Scout

## Назначение

Проверять **реально исполняемую реализацию**, когда пользователь просит живой прогон, приёмку, воспроизведение ошибки, проверку источника, терминала или отказов. Это не автоматический запуск настоящего сайта после каждой правки. Обычные тесты и список обязательных проверок определяет [VERIFICATION.md](../../../.codex/context/VERIFICATION.md).

## Главный инвариант

Вспомогательные инструменты могут **управлять**, **наблюдать** и **сопоставлять**, но не заменять исследуемый код. Нельзя считать запуск самодельного мини-парсера, выдачу заранее подготовленного JSON, искусственный успех HTTP или обход нормализации доказательством работы настоящего `anketa-scout`.

`PASS` подтверждает только реально исполненный путь. Перед запуском зафиксировать изменённый путь и наблюдаемые признаки его исполнения: результат CLI, код выхода, логи допустимых категорий, состояние файлов и реальные сетевые события, если разрешены. Синтетические unit tests не подтверждают поведение живого источника и наоборот.

## Границы безопасности

- Реальные анкеты содержат контактные данные: не писать и не публиковать посты/контакты/сырой ответ/необезличенные логи; не передавать их внешним ревьюерам, GitHub, Gist, LLM API.
- Реальный источник использовать лишь по явной потребности, соблюдая правила сайта, ограничения частоты и согласованный URL; не обходить капчу/блокировки и не расширять scope скрытно.
- Снимки и временные результаты — вне Git и отслеживаемых файлов, с ограниченным доступом и предсказуемой очисткой. Права и пути проверить **до** записи.
- Для отказов и edge cases предпочитать синтетические fixtures, локальный HTTP-сервер и штатные встроенные тестовые точки; не отключать timeout/TLS/валидацию ради успеха.
- Не менять глобальные настройки пользователя, прокси, DNS, профиль браузера или системные разрешения.

## Порядок

До выполнения читать [acceptance-procedure.md](references/acceptance-procedure.md): выбор цели, снимка/синтетики, запуск и наблюдаемость, критерии PASS/FAIL/INCOMPLETE, очистка и отчёт.

Git/PR принадлежит `scout-git-workflow`. Сравнимые замеры для утверждений об ускорении — `scout-performance-benchmarking`. Независимое ревью кода — `scout-code-review`.
