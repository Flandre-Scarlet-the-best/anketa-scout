# Описание PR: полнота и машинная проверка

## Принцип

В PR — **содержательное решение**, а не две строки и не транскрипт команд. Каноническое описание хранится в одном проверяемом источнике, который при публикации передаётся структурированно либо через UTF-8 файл; после записи обязательно читать опубликованное тело обратно.

Для ручного PR обязательны разделы уровня `##` в указанном порядке:

1. `## Цель` — исходная проблема, наблюдаемый результат.
2. `## Область изменений` — затронутые подсистемы и исключения из scope.
3. `## Реализация` — существенные архитектурные решения, поведение, контракт совместимости, версия.
4. `## Проверки` — команды, объект проверки, фактические итоги, ограничения их доказательной силы.
5. `## Производительность` — измерения сопоставимой пары «до/после» или «не измерено» с причиной.
6. `## CI` — реальные статусы проверок GitHub **текущего SHA** либо явно «ожидаются/отсутствуют».
7. `## Готовность` — Draft/Ready, блокеры, требуемые действия перед merge.
8. `## Ограничения` — что не выполнено, не воспроизводилось и чего тесты не подтверждают.

Дополнительные разделы (`Live acceptance`, `Безопасность`, `Миграция`, `CodeRabbit review и disposition`) включать по смыслу. Сохранять прежние существенные выводы, не переписывать прошлые итерации CodeRabbit как будто их не было.

## Плотность и доказательства

- Ограничить body **10 000 символами Unicode** после нормализации переводов строк: это контролируется машинно. Не жертвовать обязательной сутью ради лимита.
- Объёмные журналы, сырые логи и персональные данные **никогда** не копировать в PR. При безопасном очищенном материале отдельный Gist допускается только когда он действительно нужен; Gist по ссылке не является приватным. Не создавать его автоматически вместо достаточно полного body.
- Для выполненных проверок указывать реальные числа и причины. `cargo test` без результата/охвата не доказывает полноценную приёмку.
- Для CodeRabbit — накопительная таблица по схеме из [review-workflow.md](../../scout-coderabbit-review/references/review-workflow.md). Ни одна итерация не исчезает при обновлении; при угрозе лимита ранние итерации сжимаются по правилу того же документа.
- Нельзя выдавать локальные тесты за GitHub CI или «нет ошибок» за полноценное независимое ревью.
- При новом SHA обновлять проверки и текущий CI; устаревшая запись должна быть явно помечена.

## Проверка формата

Выполнять обязательную детерминированную проверку перед публикацией и повторное чтение после неё. Валидатор принадлежит [VERIFICATION.md](../../../../.codex/context/VERIFICATION.md) и GitHub Actions; он проверяет структуру и непустоту разделов, но **не истинность** утверждений. Истинность подтверждают фактические логи, исходники и GitHub checks.

Изменения самого валидатора не должны превращать их собственный PR в самоподтверждающийся: при проверке защитным workflow использовать проверенный код из base; недоступность такого прогона прямо сообщить. Не отключать правила ради прохождения PR.
