# Anketa Scout

Нативное Rust CLI-приложение для Windows, Linux и macOS. Получает сообщения одного
настроенного треда Двача и показывает самостоятельные анкеты
с собственным контактом автора в том же посте. Явные пол, возраст, место,
онлайн-признак и количества изображений/видео извлекаются независимо от допуска анкеты.
Неоднозначные поля остаются неизвестными; интересы и цели не классифицируются.

Для сборки нужны Rust из `rust-toolchain.toml` и системный линковщик.
Версию приложения определяет [Cargo.toml](Cargo.toml).

```text
cargo build --locked --release
cargo run --locked --release
cargo run --locked --release -- --help
cargo run --locked --release -- --version
```

Можно установить программу через `cargo install --locked --path .`, затем
запускать `anketa-scout` без аргументов. URL в команде не требуется.
Медиа показываются компактными счётчиками; вложения не скачиваются.

## Конфигурация

При первом обычном запуске программа атомарно создаёт `config.toml` с единственным
источником из [config.example.toml](config.example.toml) и сразу использует его.
Существующий файл сохраняется, включая ошибки и комментарии пользователя.

| ОС | Штатный путь |
| --- | --- |
| Windows | `%APPDATA%\anketa-scout\config.toml` |
| Linux | `$XDG_CONFIG_HOME/anketa-scout/config.toml`, обычно `~/.config/anketa-scout/config.toml` |
| macOS | `~/Library/Application Support/anketa-scout/config.toml` |

Фактический путь сообщается в stderr. `--config <ПУТЬ>` имеет приоритет над
системным каталогом; относительный путь разрешается от рабочего каталога.
Отсутствующий явно выбранный файл считается ошибкой и не создаётся.
Обычный запуск не читает `config.toml` из текущего каталога автоматически.

Для разработки можно самостоятельно скопировать образец в локальный `config.toml`
(он исключён из Git) и запустить:

```text
cargo run --locked -- --config config.toml
```

`sources` должен содержать ровно один HTTPS URL вида
`https://2ch.org/доска/res/номер.html` (также принимается `.json`). Параметры URL,
фрагменты, учётные данные, другие хосты и несколько тредов отклоняются до сети.
Неизвестные поля TOML считаются ошибкой для обнаружения опечаток.

## Распознавание и вывод

Детерминированные правила принимают пост с собственным контактом и самостоятельным
текстом сверх контактной записи. Тематика, интересы, возраст, город и качество
текста не оцениваются. Посты не склеиваются; стартовый пост, цитаты, чистые контакты
и контактные приписки не становятся анкетами. Чужая принадлежность проверяется
локально рядом с контактом, без глобальных стоп-слов.

Контакты нормализуются: Telegram — @username, почта — local@domain с сохранением
регистра локальной части, VK — slug или id..., Discord — идентификатор.
Эквивалентные контакты одной платформы объединяются; разные сохраняются.
Самостоятельная подпись @handle без платформы предполагает Telegram с меткой «предп.»;
явные Telegram, Discord, VK и MAX имеют приоритет. Некорректный для Telegram
идентификатор сохраняется с неизвестной платформой.
упоминание в предложении не считается подписью. HTML-цитаты и текст в кавычках
исключаются из свидетельств авторства; апострофы внутри слов сохраняются.
Поддерживаются локальные указания удаления пробелов, нулей, скобок,
подчёркивания и замены литерала. Непонятная инструкция не даёт достоверного контакта.

Переменная SCOUT_LOG=ERROR|WARN|INFO|DEBUG|TRACE управляет JSON-диагностикой в
stderr (по умолчанию INFO). DEBUG содержит решения по номерам постов, TRACE —
платформы и операции восстановления; значения контактов и тексты не логируются.
Локальный снимок можно проверить без сети: SCOUT_AUDIT_JSON задаёт путь для
cargo test --locked --test offline_audit -- --ignored --nocapture.
Перед сравнением сверяйте SHA-256 файла; обычные тесты снимка не требуют.

В stdout выводятся Unicode-таблицы: в начальной сводке указан URL треда, затем
анкеты в исходном порядке. Полный просмотр показывает очищенное описание, все
контакты с их типами, номер поста, локальную дату ОС со смещением и распознанные
сведения об авторе.
Контактные записи и служебные ссылки-ответы удаляются из отображаемого описания.
Исходный текст, URL отдельных постов и метаданные вложений сохраняются в модели.
В выводе показывается URL треда, но не ссылки на отдельные посты и не карточки вложений.
Строка date источника не подменяет отсутствующий/некорректный timestamp.
В широком окне используются колонки «Пост / дата», «Контакты», «Текст»; меньше
76 колонок — последовательные таблицы полей. Текст получает дополнительное место
при расширении окна. Длинные слова и URL переносятся без сокращения, составные
символы, CJK и эмодзи учитываются по визуальной ширине. Размер берётся у stdout,
для файла/pipe или неизвестного размера используется ширина 96 колонок.
При ширине меньше 8 программа использует минимальную таблицу шириной 8:
данные сохраняются, но физически вместить её в такое окно невозможно.

```text
anketa-scout --view compact
anketa-scout --view full --theme light
anketa-scout --color never
anketa-scout --color always --theme dark
anketa-scout --no-color
```

`--view compact` явно обозначает обзор и сокращает только текст анкеты до превью
в пределах 100 визуальных колонок с многоточием при сокращении. Контакты остаются
полными; отдельные ссылки на посты и карточки вложений не показываются. Полный
просмотр: `--view full`.
Пустой тред и отсутствие подходящих анкет имеют разные сообщения без фиктивных строк.

`--color auto` включает цвет только для поддерживаемого терминала; учитывает
`NO_COLOR` и `TERM=dumb`. `--color always` явно включает цвет, включая файл/pipe,
и имеет приоритет над `NO_COLOR`; `--color never` отключает его. `--no-color`
имеет высший приоритет, в том числе совместно с `--color always`.
`--theme dark|light` выбирает контрастную палитру для соответствующего фона;
по умолчанию используется dark, автоматического определения фона нет.
RGB выбирается по признакам truecolor (`COLORTERM`, Windows Terminal или сведения
терминала), затем используются 256 цветов при `TERM=…256color`, иначе 16.
Контакты и показатели выделены, метаданные и рамки приглушены; цвет не несёт
единственного обозначения смысла. Гиперссылок OSC 8 нет: URL всегда видны текстом.

Управляющие символы и невидимые bidi-команды удаляются. Рамочные символы из
источника, `|` и маркер `›` показаны видимыми кодами вида `\u{2502}`.
Каждая физическая строка данных, включая продолжение после переноса, остаётся
в собственной ячейке с доверенным маркером `›`; переводы строк в метаданных
заменяются пробелами. Заголовки и границы создаёт только программа.
Контакты и содержимое постов не пишутся в диагностику. Перенаправленный stdout
содержит анкеты — хранить его следует как пользовательские данные.

Во время HTTP-запроса в подходящем stderr-терминале показывается спиннер
«Получение треда…». Он очищается до вывода результата или ошибки, включая Ctrl+C.
В файле/pipe, при `TERM=dumb`, неизвестных возможностях или слишком узком stderr
анимации нет. Промежуточные анкеты и фиктивные проценты не выводятся.
Это обычный CLI: без альтернативного экрана, raw mode и интерактивной навигации.

HTTP-клиент обращается к JSON треда, запрещает перенаправления, ограничивает
подключение 10 секундами, весь запрос 40 секундами, распакованный ответ 20 МиБ,
тред 20 000 сообщений, комментарий 128 КиБ и вложения 100 на пост.
Счётчик `posts_count`, уникальность номеров, происхождение и наличие вступительного
поста проверяются; неполный ответ не выдаётся как полный. В однократном режиме
автоматических повторов нет; обхода капч нет. Ответ Двача без OP, в том числе с нулём сообщений, считается
неполным; отсутствие подходящих анкет в полном треде — успешный результат.
Ctrl+C отменяет ожидающее получение и завершает программу с кодом 130.
Конфиг должен быть обычным файлом; каналы и устройства отклоняются.

## Наблюдение

Без `--watch` программа получает один снимок и завершается. Пример:

```text
anketa-scout --watch
anketa-scout --watch --interval 1m
```

Интервал по умолчанию `20s`, доступны целые `s`, `m`, `h` от 1 секунды до 24 часов.
Один `--interval` не включает наблюдение. Пауза отсчитывается после завершения
предыдущего запроса и вывода, запросы не накладываются. После начального JSON
используется только `/api/mobile/v2/after/{board}/{thread}/{post}` с граничным ID.
Нормализация и классификация общие; курсор учитывает также отклонённые посты.
Граничный дубликат не выводится, пустой пакет не создаёт таблиц. При временной
сетевой ошибке, таймауте или 429 курсор сохраняется; наблюдение делает не более
трёх повторов с удвоением задержки до часа (но не меньше выбранного интервала).
Другие ошибки и исчерпание повторов завершают наблюдение.
Диагностика и интерактивный спиннер ожидания идут в stderr; Ctrl+C завершает
ожидание, запрос или вывод. В pipe анимации нет.


| Код завершения | Значение |
| --- | --- |
| 0 | Полный результат, включая отсутствие анкет; закрытый получателем stdout |
| 2 | Аргументы или конфигурация |
| 3 | Сеть или таймаут |
| 4 | Нет треда, ограничен доступ или частота запросов |
| 5 | Неверный формат ответа |
| 6 | Неполный ответ |
| 7 | Превышены ограничения входных данных |
| 8 | Ошибка записи вывода или подключения обработки Ctrl+C |
| 130 | Отмена пользователем |

Команды проверок, платформенная матрица CI и поведенческие доказательства
находятся у [владельца проверочной политики](.codex/context/VERIFICATION.md).

Разбор комментариев HTML нужен внутри подтверждённого JSON-формата, отдельной
HTML-загрузки треда нет. Справка источника: [Двач API](https://2ch.org/abu/res/42375.html).
TUI, база, кеш, фильтры характеристик и несколько источников пока не реализованы.
