# Разработка и конфигурации

## Текущее устройство

Один Cargo-пакет содержит библиотеку и бинарный CLI `anketa-scout`.
Границы определены [архитектурой](ARCHITECTURE.md): `domain` — предметные значения
и распознавание; `application` — координация с подставляемым получением сообщений;
`source` — URL и JSON/HTML Двача; `transport` — ограниченный HTTP;
`config` — пользовательский TOML; `output` — безопасное представление;
`main` связывает конкретные реализации и обрабатывает аргументы.
SQLite, TUI и долговременного кеша нет. Команды запуска и выбор пользовательского
конфига описаны в [README](../../README.md).

Выбор зависимостей и их потребители зафиксированы в
[архитектуре](ARCHITECTURE.md#зависимости-текущего-cli).

## Rust и локальная среда

`rust-toolchain.toml` фиксирует проверенный стабильный Rust без привязки к host triple;
rustfmt и Clippy входят в минимальный профиль разработки. `rustfmt.toml` использует
стабильную настройку LF. Редакция Rust объявлена в Cargo.
Версии и MSRV определяются [VERSIONING.md](VERSIONING.md).

Работать можно нативно на Windows, Linux и macOS. Для нативной сборки нужны средства
линковки соответствующей платформы; проект не требует WSL. Команды документации
должны быть переносимыми либо явно иметь отдельные платформенные варианты.
Диск и расположение рабочей копии пользователя не становятся проектным контрактом.

Rust-код должен обрабатывать ожидаемые ошибки без panic, ограничивать
внешний ввод и ресурсы, поддерживать отмену I/O. Новую зависимость или feature
обосновывать конкретной потребностью, переносимостью и MSRV; unsafe требует
отдельного технического обоснования и проверки, а не используется по умолчанию.
Публичное поведение изменять вместе с документацией и применимыми проверками.

## Git и данные

`.gitattributes` задаёт LF для текстов и отключает нормализацию бинарных файлов.
`.editorconfig` согласует UTF-8 без BOM, LF и финальный перевод строки.
Не менять глобальный Git, кодировки консоли или профиль оболочки ради проекта.
`.gitignore` исключает кеш сборки, локальные данные, секреты и артефакты ОС;
`Cargo.lock` приложения отслеживается. Личный `/config.toml` исключён из Git;
`config.example.toml` отслеживается и служит содержимым нового штатного конфига.
Игнорирование Git не заменяет контроль конфиденциальности и уже отслеживаемых файлов.
Пользовательские данные по умолчанию хранятся вне рабочей копии по архитектурному контракту;
`data/`, `cache/`, `local/` и `.codex/local/` — защитные исключения для локальной работы.

## Renovate и CodeRabbit

`renovate.json` — владелец настроек обновления: `config:best-practices`, `group:all`,
обычные major/minor/patch, Rust toolchain/MSRV и GitHub Actions в общей группе,
без автоматического слияния. Замена зависимостей и самостоятельное обслуживание
файлов фиксации зависимостей не объединяются с обычными обновлениями.
Обслуживание `Cargo.lock` включено явно.
Обновления безопасности проходят отдельным оперативным каналом со своим
лимитом и без обычного ожидания. Поэтому буквально один PR не гарантируется.
Панель обновлений зависимостей и лимиты ограничивают шум, а не служат доказательством проверки.
Обнаружение уязвимостей зависит от доступных сервису предупреждений и прав доступа.
Установка приложения Renovate и настройки GitHub не выполняются конфигурационным PR.

`.coderabbit.yaml` адаптирует ручное ревью под владельцев проекта. Автоматическое
ревью, запрос изменений и автоматические правки отключены. Условия запуска и
оценки замечаний принадлежат [scout-coderabbit-review](../../.agents/skills/scout-coderabbit-review/SKILL.md).
Наличие YAML не запускает сервис и не разрешает его установку.

Первичные источники для изменения конфигураций:
[Renovate](https://docs.renovatebot.com/configuration-options/),
[group:all](https://docs.renovatebot.com/presets-group/#all),
[Rust toolchain manager](https://docs.renovatebot.com/modules/manager/rust-toolchain/),
[CodeRabbit](https://docs.coderabbit.ai/reference/configuration).
