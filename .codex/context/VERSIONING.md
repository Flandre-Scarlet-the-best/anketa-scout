# Версии приложения и Rust

Приложение следует SemVer. Единственный источник версии — `package.version`
корневого `Cargo.toml`. CLI и метаданные получают версию из Cargo, без ручных копий.
GitHub Release и теги — отдельные явно порученные операции.

В каждой задаче, меняющей поведение, сверить источник версии со свежей `origin/main`,
оценить необходимость повышения версии и включить решение и изменение в PR. Исправление ошибки
требует patch, новая совместимая возможность — minor, несовместимость стабильного
публичного контракта — major. До `1.0.0` несовместимые изменения повышают minor
с явным описанием миграции. Чистая документация и инфраструктура без изменения
поведения приложения сами по себе повышения версии не требуют. Не повышать версию механически
повторно, если текущий PR уже содержит нужное повышение относительно main.

## Toolchain и MSRV

Каноническая MSRV объявлена в `package.rust-version` корневого `Cargo.toml`.
Использовать только опубликованные стабильные версии, без beta/nightly.
Для этого проекта закреплённый toolchain и MSRV должны соответствовать одному
стабильному релизу Rust; хранить полный номер `X.Y.Z`.

Renovate обновляет `rust-toolchain.toml` встроенным `rust-toolchain` manager,
а каноническое поле `rust-version` — ограниченным корневым `Cargo.toml` regex manager.
Встроенный Cargo manager не извлекает MSRV; это проверено по
[его схеме](https://github.com/renovatebot/renovate/blob/main/lib/modules/manager/cargo/schema.ts).
Обе зависимости имеют имя `rust`, источник `rust-version` и общий групповой PR;
разрешены только полные стабильные номера, стратегия — `replace`.
Тест `cargo_version_and_toolchain_are_canonical_and_synchronized` запрещает
расхождение двух значений в CI. При изменении Renovate повторять фактическое
извлечение обоих значений и проверку применяемой группировки: одна схема и
простая группировка PR не доказывают синхронность обновления.
